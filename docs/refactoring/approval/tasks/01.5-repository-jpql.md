# 단계 1.5: Repository JPQL 정합

## 목적

단계 1에서 `Approval.approvalStatus` / `Approver.approverStatus`를 Enum + `@Enumerated(EnumType.STRING)`으로 전환했으나, Repository의 JPQL은 여전히 한글 문자열 리터럴과 비교하고 있다.

DB 값은 이미 영문 Enum 값으로 마이그레이션되었으므로, 해당 쿼리들은 **예외 없이 조용히 0건을 반환**한다. 컴파일과 부팅이 모두 통과하기 때문에 기존 검증 절차로는 발견되지 않는다.

> **실측 확인 (2026-07-24)**
> ```sql
> SELECT COUNT(*) FROM APPROVAL WHERE APPROVAL_STATUS = '임시저장';  -- 0건
> SELECT COUNT(*) FROM APPROVAL WHERE APPROVAL_STATUS = 'TEMP_SAVED'; -- 다수
> SELECT COUNT(*) FROM APPROVER WHERE APPROVER_STATUS = '대기';       -- 0건
> SELECT COUNT(*) FROM APPROVER WHERE APPROVER_STATUS = 'PENDING';    -- 다수
> ```
> `bootRun` 정상 기동 확인 (Started Application in 10.037 seconds).
> 즉 부팅 시점 예외가 아니라 **런타임 무성 실패(silent failure)** 이다.

**현재 동작하지 않는 기능**
- 결재 대기함 조회
- 임시저장함 조회 / 검색 / 카운트
- 반려 처리자 조회

## 이 단계가 로드맵에 추가된 배경

`spec.md`의 문제 목록 A~L은 Service / Controller 계층 분석에서 도출되었고, **Repository 계층이 누락**되어 있었다. Entity의 타입 변경이 Repository로 전파된다는 점이 명세에 반영되지 않은 결과다.

→ `spec.md`에 **문제 M: Repository 한글 리터럴 (JPQL + 네이티브)** 항목을 추가할 것.
→ 이후 모든 단계의 검증에 `bootRun` + 수동 API 확인을 포함할 것. `compileJava`만으로는 부족하다.
→ 한글 리터럴은 JPQL뿐 아니라 `nativeQuery = true` 쿼리에도 존재한다. 둘은 교체 방식이 다르므로(아래 B·B-2) 분리해서 처리한다.

> **JPQL과 네이티브는 처리 방식이 다르다.**
> - **JPQL**: Hibernate가 Enum을 인식하므로 전체 경로 상수 표기(`...ApproverStatus.PENDING`)를 쓴다.
> - **네이티브**: SQL이 DB에 그대로 나가므로 Enum 상수를 쓸 수 없다. DB에 저장된 **문자열 값**을 직접 써야 한다. V1·V2 마이그레이션으로 DB에는 `'PENDING'` / `'PROCESSING'`이 저장되어 있으므로 그 값으로 교체한다.

**(3) 메서드 네이밍 오류 + 파라미터 타입 — 1곳**

```java

        @Param("approvalNo") String approvalNo,
        @Param("approverStatus") String approverStatus);
```

## 세부 작업 지시

### A. JPQL 리터럴 교체 방식

JPQL에서 Enum을 비교할 때는 **완전한 패키지 경로를 포함한 상수 표기**를 사용한다.

```java
// Before
@Query("SELECT a FROM Approval a WHERE a.memberId = :memberId AND a.approvalStatus = '임시저장'")

// After
@Query("SELECT a FROM Approval a WHERE a.memberId = :memberId " +
       "AND a.approvalStatus = com.insider.login.approval.enums.ApprovalStatus.TEMP_SAVED")
```

**이 방식을 택한 이유**: 메서드 시그니처가 그대로 유지되어 Service 호출부 변경이 최소화된다. 파라미터 바인딩 방식(`:status`)은 더 유연하지만 모든 호출부를 함께 고쳐야 하므로 이 단계의 범위를 넘어선다.

축약형(`ApprovalStatus.TEMP_SAVED`)은 Hibernate 버전에 따라 해석이 달라질 수 있으므로 **반드시 전체 경로를 사용한다.**

### B. 변환 매핑표

**JPQL (전체 경로 Enum 상수 표기)**

| 기존 리터럴 | 위치 | 교체 대상 |
|---|---|---|
| `'임시저장'` | ApprovalRepository (6곳) | `com.insider.login.approval.enums.ApprovalStatus.TEMP_SAVED` |
| `'대기'` | ApproverRepository JPQL (1곳) | `com.insider.login.approval.enums.ApproverStatus.PENDING` |

**네이티브 쿼리 (DB 저장 문자열 리터럴)**

| 기존 리터럴 | 위치 | 교체 대상 |
|---|---|---|
| `'대기'` | ApproverRepository 네이티브 (1곳) | `'PENDING'` |
| `'처리 중'` | ApproverRepository 네이티브 (1곳) | `'PROCESSING'` |

**Service 인자**

| 기존 리터럴 | 위치 | 교체 대상 |
|---|---|---|
| `"반려"` | ApprovalService (1곳) | `ApproverStatus.REJECTED` |

> ⚠️ **네이티브 쿼리 문자열은 Enum 상수명과 우연히 일치할 뿐, 코드상 Enum과 연결되지 않는다.** 향후 Enum 상수를 개명하면(예: `PENDING` → `WAITING`) 이 네이티브 문자열은 자동으로 따라오지 않으므로 함께 고쳐야 한다. 이 사실을 해당 쿼리 위에 주석으로 남기고 보고서에도 기록한다. (근본 해결 — 네이티브를 JPQL로 재작성 — 은 이 단계 범위 밖. Stage 6에서 재검토)

### B-2. 네이티브 쿼리 리터럴 교체 (`findStandByApprovalsByTitleNative`)

이 쿼리는 `nativeQuery = true`이므로 Enum 상수 표기를 쓸 수 없다. DB에 저장된 문자열로 교체한다.

```java
// Before
"WHERE d.approver_status = '대기' " +
"WHERE c.approval_status = '처리 중') " +

// After
"WHERE d.approver_status = 'PENDING' " +
"WHERE c.approval_status = 'PROCESSING') " +
```

그리고 이 메서드 위에 개명 취약성 주석을 남긴다:

```java
// 주의: 네이티브 쿼리이므로 Enum 상수와 연결되지 않는다.
// 'PENDING' = ApproverStatus.PENDING, 'PROCESSING' = ApprovalStatus.PROCESSING 의 DB 저장값.
// Enum 상수 개명 시 이 리터럴도 함께 수정해야 함. (Stage 6에서 JPQL 재작성 검토)
```

### C. ApproverRepository 메서드 개명

```java
// Before
Optional<Approver> findByApprovalNoAndApprovalStatus(
        @Param("approvalNo") String approvalNo,
        @Param("approverStatus") String approverStatus);

// After
@Query("SELECT a FROM Approver a WHERE a.approvalNo = :approvalNo " +
       "AND a.approverStatus = :approverStatus")

        @Param("approvalNo") String approvalNo,
        @Param("approverStatus") ApproverStatus approverStatus);
```

기존 메서드명은 `ApprovalStatus`라고 되어 있으나 실제로는 `approverStatus`를 조회한다. 명백한 네이밍 오류이므로 이 단계에서 함께 교정한다.
