## 왜 이 파일이 필요한가

작업 04·05 명세가 `선례 S4`·`선례 S2`처럼 번호로 참조했으나,
**그 번호를 정의한 문서가 리포 안에 없었다.** 번호는 인계 문서 §4에 존재했지만

그 결과 리포만 뒤진 세션이 `S2`·`S4`가 가리키는 대상을 찾지 못하고
"번호 체계가 존재하지 않는다"고 오판했다. **정본이 리포 밖에 있으면 이 사고는 반복된다.**

번호를 새로 매기지 않는다. 인계 문서 §4의 번호가 그대로 정본이다.

## 1. 선례 (S) — 후속 작업이 따르는 판단 기준

### 작업 E (읽기 인가)

| # | 선례 |
|---|---|
| S1 | **읽기 차단은 404, 쓰기 차단은 403.** 읽기는 GET이라 열거 비용이 0이므로 존재를 은폐한다 |
| S2 | **인가 판정은 관계로만.** role(ADMIN/MEMBER) 분기를 넣지 않는다 — ADMIN도 관계 없으면 차단 |
| S3 | **인가는 새 public 진입점에 넣고 기존 내부용 메서드는 package-private으로 낮춘다.** 목록이 상세 메서드를 항목마다 호출하므로, 기존 메서드에 인가를 넣으면 목록이 통째로 깨진다 |
| S4 | **응답 구조는 바꾸지 않는다.** 전부 아니면 전무 — 부분 권한 개념을 만들지 않는다 |
| S5 | 차단·비차단을 `log.warn`으로 구분 기록 |

### 작업 F (인증 실패 응답)

| # | 선례 |
|---|---|
| **S6** | **응답 본문을 건드리지 않는 처방은 판정이 두 숫자로 끝난다** — 본문 해시 동일 + 상태 코드. 본문까지 바꾸면 회귀 판정과 처방 판정이 뒤섞인다 |
| **S7** | **필터·핸들러는 `GlobalExceptionHandler`가 못 잡는다.** DispatcherServlet 밖이라 `ErrorCode`/`ErrorResponse`로 위임할 경로가 없고, **상태 코드 직접 세팅이 유일한 수단이다.** 같은 기준선 안에서 대조 실증됨 — 캡처 `07`(`ErrorResponse` C999, 90B) vs `16`·`17`(Spring 기본 에러, 8~9KB) |
| **S8** | **`catch`가 커밋된 응답에 도달할 수 있으면 `isCommitted()` 가드를 둔다.** 없으면 `setStatus`가 조용히 무시되고, 무시됐다는 사실도 남지 않는다 |
| **S9** | **인증 실패는 401 단일.** 예외 종류별로 403을 섞으면 프론트가 `=== 401`만 보므로 그 경우만 조용히 실패한다 |

> ⚠ **S9 정정 (2026-08-21, 작업 05 명세 리뷰).** 인계 문서 §4 원문은
> "인증/인가 실패 상태 코드는 단일화한다"였으나, **인가 실패는 S1이 404/403으로 가른다.**
> 작업 F의 사정권은 인증뿐이었고 근거("프론트가 `=== 401`만 본다")도 인증 전용이므로
> **"인증"으로 좁혔다.** 원문을 그대로 두면 S1과 정면 충돌해 다음 세션이 어느 쪽을 따를지 갈린다.
>
> **이 파일에서 원문을 고친 것은 이 한 행뿐이다.** 원문이 틀린 경우까지 보존하면
> 정본이 오류의 화석이 된다 — 다만 **소리 없이 고치지 않는다.** 그래서 이 각주가 있다.

> **S7 합침 (2026-08-21, 같은 리뷰).** 인계 문서 §4에는 증거만, `AGENTS.md`에는 처방만 있었다.
> **처방과 증거가 둘 다 있어야 선례로 기능**하므로 두 문장을 합쳤다. 내용 변경은 없다.

## 3. 번호 부여 규칙

- **S** = 처방 판단 기준. "이런 상황이면 이렇게 하라"의 형태를 갖출 때만 부여한다.
  단순한 사실·제약(예: "브라우저 WebSocket은 헤더를 실을 수 없다")은 S가 아니라 `spec.md` §4-3 등재다
- **P** = 검증 방법론. 처방이 아니라 "어떻게 확인하는가"
- **R** = 특정 작업의 위험 항목 중 이후 작업에도 되풀이 적용되는 것 (현재 R11 하나)
- 번호는 **작업 완료 시점에 그 작업의 보고서가 확정**하고, 이 파일에 추가한다.
  명세 단계에서 "`S11` 후보"처럼 미리 예약하지 않는다 — 실증되지 않은 번호가 참조되기 시작한다
  > **`S10`이 이 규칙대로 부여된 첫 사례다.** 05 명세 v2는 WebSocket 건의 승격을 검토하며
  > **번호를 예약하지 않았고**(D6), 실제로 승격된 것은 명세에 없던 다른 건이었다.
- ⚠ **`docs/refactoring/**`의 `S0`~`S11`은 다른 체계다** — 그쪽은 **스모크 시나리오** 번호이고
